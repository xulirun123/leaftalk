# 群聊邀请流程测试文档

## 功能概述

实现了完整的群聊邀请流程，包括两种情况：
1. **未开启群聊邀请确认**：群主/管理员和普通成员邀请都直接加入
2. **开启群聊邀请确认**：群主/管理员邀请直接加入，普通成员邀请需要审核

## 测试场景

### 场景一：未开启群聊邀请确认

#### 1.1 群主/管理员邀请好友
**测试步骤：**
1. 以群主或管理员身份登录
2. 进入群聊详情页
3. 点击"邀请好友"
4. 选择要邀请的好友
5. 点击"完成"

**预期结果：**
- 邀请人收到群聊邀请卡片消息
- 被邀请人收到群聊邀请卡片消息
- 被邀请人点击邀请卡片，弹出确认对话框
- 被邀请人点击"加入"，直接加入群聊
- 群聊中显示系统消息："XXX 通过邀请链接加入了群聊"

#### 1.2 普通成员邀请好友
**测试步骤：**
1. 以普通成员身份登录
2. 进入群聊详情页
3. 点击"邀请好友"
4. 选择要邀请的好友
5. 点击"完成"

**预期结果：**
- 邀请人收到群聊邀请卡片消息
- 被邀请人收到群聊邀请卡片消息
- 被邀请人点击邀请卡片，弹出确认对话框
- 被邀请人点击"加入"，直接加入群聊
- 群聊中显示系统消息："XXX 通过邀请链接加入了群聊"

### 场景二：开启群聊邀请确认

#### 2.1 开启群聊邀请确认
**测试步骤：**
1. 以群主身份登录
2. 进入群聊详情页
3. 点击"群管理"
4. 开启"群聊邀请确认"开关

**预期结果：**
- 开关状态变为开启
- 显示"群聊邀请申请"菜单项

#### 2.2 群主/管理员邀请好友（开启确认后）
**测试步骤：**
1. 以群主或管理员身份登录
2. 进入群聊详情页
3. 点击"邀请好友"
4. 选择要邀请的好友
5. 点击"完成"

**预期结果：**
- 邀请人收到群聊邀请卡片消息
- 被邀请人收到群聊邀请卡片消息
- 被邀请人点击邀请卡片，弹出确认对话框（不需要输入申请理由）
- 被邀请人点击"加入"，直接加入群聊
- 群聊中显示系统消息："XXX 通过邀请链接加入了群聊"

#### 2.3 普通成员邀请好友（开启确认后）
**测试步骤：**
1. 以普通成员身份登录
2. 进入群聊详情页
3. 点击"邀请好友"
4. 选择要邀请的好友
5. 点击"完成"

**预期结果：**
- 邀请人收到群聊邀请卡片消息
- 被邀请人收到群聊邀请卡片消息
- 被邀请人点击邀请卡片，弹出确认对话框（显示申请理由输入框）
- 被邀请人输入申请理由（可选）
- 被邀请人点击"发送申请"，提交申请
- 显示提示："申请已提交，等待群主/管理员审核"
- 邀请卡片状态变为"等待审核"

#### 2.4 群主/管理员查看和处理申请
**测试步骤：**
1. 以群主或管理员身份登录
2. 进入群聊详情页
3. 点击"群管理"
4. 查看"群聊邀请申请"右侧的红色未读数字
5. 点击"群聊邀请申请"
6. 查看申请列表

**预期结果：**
- "群聊邀请申请"右侧显示未读申请数量（红色数字）
- 申请列表显示所有待处理的申请
- 每个申请显示：头像、昵称、申请理由
- 可以点击"接受"或"拒绝"按钮

#### 2.5 同意申请
**测试步骤：**
1. 在申请列表中点击"接受"按钮

**预期结果：**
- 申请状态变为"已同意"
- 被邀请人收到通知："群聊申请已通过"
- 被邀请人的邀请卡片状态变为"已加入"
- 群聊中显示系统消息："XXX 通过邀请加入了群聊"
- 其他管理员和群主看到的申请也变为"已同意"状态

#### 2.6 拒绝申请
**测试步骤：**
1. 在申请列表中点击"拒绝"按钮

**预期结果：**
- 申请状态变为"已拒绝"
- 被邀请人收到通知："群聊申请被拒绝"
- 被邀请人的邀请卡片状态变为"申请被拒"
- 其他管理员和群主看到的申请也变为"已拒绝"状态

## 技术实现

### 前端修改
1. **InviteToGroup.vue**：修改为使用 `/api/groups/:groupId/invite-request` 接口
2. **GroupInviteCard.vue**：
   - 添加申请理由输入框
   - 根据邀请人角色和群设置判断是否需要审核
   - 支持不同状态的显示（pending、joined、waiting、approved、rejected）
3. **GroupManagement.vue**：
   - 添加未读申请数量显示
   - 监听 WebSocket 事件更新未读数量
4. **GroupInviteRequests.vue**：
   - 添加顶部导航栏
   - 显示申请列表
   - 支持同意/拒绝操作

### 后端API
1. **POST /api/groups/:groupId/invite-request**：发送群聊邀请
2. **POST /api/groups/join-by-invite**：通过邀请码加入群聊（支持申请理由）
3. **GET /api/groups/invite-link-info**：获取邀请链接信息（判断是否需要审核）
4. **GET /api/groups/:groupId/invite-requests**：获取邀请申请列表
5. **GET /api/groups/:groupId/invite-requests/unread-count**：获取未读申请数量
6. **POST /api/groups/:groupId/invite-requests/:requestId/accept**：同意申请
7. **POST /api/groups/:groupId/invite-requests/:requestId/reject**：拒绝申请

### WebSocket事件
1. **new_group_invite_request**：新的邀请申请（通知群主和管理员）
2. **group_join_approved**：申请通过（通知申请人）
3. **group_join_rejected**：申请被拒（通知申请人）

## 数据库表
- **group_invite_links**：群聊邀请链接表
- **group_join_requests**：群聊加入申请表

## 注意事项
1. 群主和管理员的邀请始终直接加入，不受"群聊邀请确认"设置影响
2. 普通成员的邀请在开启"群聊邀请确认"后需要审核
3. 任意一个管理员或群主处理申请后，其他人看到的申请状态也会更新
4. 查看申请列表后，未读数量清零
5. 申请理由为可选项，最多100字符
